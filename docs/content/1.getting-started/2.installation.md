## Avec Docker Compose

::steps{level="3"}

### Démarrer la stack

```bash [Terminal]
docker compose up -d --build
```

Cela lance PostgreSQL, l'API (qui applique les migrations au démarrage), le worker d'envoi, le front et Mailpit, un faux serveur SMTP pour le développement.

### Créer le compte administrateur

Ouvrez http://localhost:3000. Tant qu'aucun compte n'existe, Rocket Print affiche la page **Configuration initiale** : nom, email et mot de passe (12 caractères minimum) de l'administrateur. Une fois le compte créé, vous êtes connecté et redirigé vers les Réglages. La page n'est plus jamais accessible ensuite.

::warning
Tant que le compte n'est pas créé, la première personne qui ouvre l'application peut le créer. Si l'instance est accessible par d'autres avant que vous la configuriez, définissez `SETUP_TOKEN` : la page demandera ce jeton.

```bash [.env]
SETUP_TOKEN=un-secret-connu-de-vous-seul
```
::

Vous pouvez aussi créer l'administrateur en ligne de commande, par exemple dans un script de déploiement :

```bash [Terminal]
docker compose exec api php bin/console app:user:create admin@exemple.com 'un-mot-de-passe-long' --admin
```

::note
Avec LDAP, si les comptes sont synchronisés avant toute configuration, la page de configuration disparaît : les administrateurs viennent alors du groupe `LDAP_ADMIN_GROUP_DN`, ou de la commande ci-dessus.
::

### Se connecter

| Adresse | Contenu |
|---|---|
| http://localhost:3000 | Application Rocket Print |
| http://localhost:8000/api/docs | Documentation OpenAPI de l'API |
| http://localhost:8025 | Mailpit (emails envoyés en développement) |

::

## Images Docker

La CI publie deux images sur GitHub Container Registry, pour `main`, `develop` et les tags `vX.Y.Z` :

- `ghcr.io/fayouz/rocket-print-api` : API, et aussi le worker, en changeant la commande par `php bin/console messenger:consume async scheduler_default` (envois et tâches planifiées) ;
- `ghcr.io/fayouz/rocket-print-front` : front Nuxt.

Leur version (`git describe --tags`) s'affiche dans l'application. Pour les mettre à jour depuis l'interface, voir [Mises à jour](/administration/updates).

## Configuration

### API

| Variable | Rôle | Défaut |
|---|---|---|
| `DATABASE_URL` | Connexion PostgreSQL | — |
| `APP_SECRET` | Secret Symfony | — |
| `JWT_PASSPHRASE` | Passphrase des clés JWT (`config/jwt/`, à monter en volume) | — |
| `MAILER_DSN` | Transport SMTP, ex. `smtp://user:pass@smtp.exemple.com:587` | — |
| `MAILER_DEFAULT_FROM` | Adresse d'expédition par défaut à l'installation, ex. `Rocket Print <no-reply@exemple.com>`. Elle initialise les [adresses d'expédition](/administration/settings) au premier démarrage ; on les gère ensuite dans les Réglages. | — |
| `MESSENGER_TRANSPORT_DSN` | File d'attente des envois | `doctrine://default` |
| `ATTACHMENTS_DIR` | Dossier des pièces jointes. **Doit être partagé par l'API et le worker** (volume Docker `attachments`). | `var/attachments` |
| `ATTACHMENT_MAX_SIZE` | Taille maximale d'un fichier, en octets. Au-delà de 16 Mo, augmentez aussi `upload_max_filesize` et `post_max_size` dans `docker/php.ini`. | `10485760` (10 Mo) |
| `ATTACHMENTS_MAX_TOTAL_SIZE` | Taille maximale des pièces jointes d'un email, en octets | `26214400` (25 Mo) |
| `EMBED_TOKEN_TTL` | Durée de vie des jetons d'embed (secondes) | `900` |
| `CORS_ALLOW_ORIGIN` | Origines autorisées à appeler l'API depuis un navigateur (regex) | localhost |
| `MAILBOX_ENCRYPTION_KEY` | Clé de chiffrement des mots de passe des [boîtes d'envoi](/administration/mailboxes). Vide : dérivée de `APP_SECRET`. La changer oblige à ressaisir les mots de passe. | — |
| `MAILBOX_TIMEOUT` | Délai maximal des connexions SMTP et IMAP des boîtes d'envoi (secondes) | `15` |
| `SETUP_TOKEN` | Jeton demandé par la page de configuration initiale (création du premier administrateur). Vide : pas de jeton. | — |
| `UPDATE_REPOSITORY` | Dépôt GitHub dont les nouvelles versions sont signalées. Vide : pas de vérification. Voir [Mises à jour](/administration/updates). | `fayouz/rocket-print` |
| `UPDATER_TOKEN` | Active la mise à jour en un clic, avec le service `updater` (profil `updater`) | — |
| `RUN_MIGRATIONS` | `1` pour appliquer les migrations au démarrage du conteneur | `0` |

Les variables LDAP sont décrites dans [Utilisateurs et LDAP](/administration/users-ldap).

### Tâches planifiées

```bash [crontab]
# Synchronisation de l'annuaire (si LDAP est activé)
*/30 * * * *  docker compose exec -T api php bin/console app:ldap:sync
# Suppression des pièces jointes téléversées mais jamais envoyées (plus de 24 h)
0 3 * * *     docker compose exec -T api php bin/console app:attachments:purge --older-than="24 hours"
```

### Front

| Variable | Rôle |
|---|---|
| `NUXT_PUBLIC_API_BASE` | URL de l'API vue par le navigateur. **Vide** : le front relaie `/api` vers l'API (une seule URL publique, pas de CORS). |
| `NUXT_API_INTERNAL_BASE` | URL de l'API vue par le serveur du front, ex. `http://api:80` |

::warning
En production, changez `APP_SECRET` et `JWT_PASSPHRASE`, montez les clés JWT dans un volume persistant, et servez le front et l'API en **HTTPS** : les navigateurs exigent HTTPS pour les iframes tierces et les cookies sécurisés.
::
