## Avec Docker Compose

::steps{level="3"}

### Démarrer la stack

```bash [Terminal]
docker compose up -d --build
```

Cela lance PostgreSQL, l'API (qui applique les migrations au démarrage), le worker d'impression et le front. L'image de l'API contient `smbclient`, utilisé par le connecteur Samba.

### Créer le compte administrateur

Ouvrez http://localhost:3300. Tant qu'aucun compte n'existe, Rocket Print affiche la page **Configuration initiale** : nom, email et mot de passe (12 caractères minimum) de l'administrateur. La page n'est plus jamais accessible ensuite.

::warning
Tant que le compte n'est pas créé, la première personne qui ouvre l'application peut le créer. Si l'instance est accessible par d'autres avant que vous la configuriez, définissez `SETUP_TOKEN` : la page demandera ce jeton.
::

Vous pouvez aussi créer l'administrateur en ligne de commande :

```bash [Terminal]
docker compose exec api php bin/console app:user:create admin@exemple.com 'un-mot-de-passe-long' --admin
```

### Déclarer les imprimantes

Dans **Administration → Imprimantes**, ajoutez vos imprimantes puis **Tester la connexion**. Voir [Imprimantes](/administration/printers).

::

| Adresse | Contenu |
|---|---|
| http://localhost:3300 | Application Rocket Print |
| http://localhost:8300/api/docs | Documentation OpenAPI de l'API |

## Réseau

Le worker doit joindre les imprimantes et les serveurs d'impression :

- **Samba** : port TCP 445 du serveur d'impression ;
- **IPP** : port 631 de l'imprimante ou du serveur CUPS (ou le port indiqué dans l'adresse).

Dans Docker, les conteneurs sortent par le réseau de l'hôte : vérifiez que l'hôte a accès au réseau des imprimantes.

## Images Docker

La CI publie deux images sur GitHub Container Registry, pour `main`, `develop` et les tags `vX.Y.Z` :

- `ghcr.io/fayouz/rocket-print-api` : API, et aussi le worker, avec la commande `php bin/console messenger:consume async scheduler_default` ;
- `ghcr.io/fayouz/rocket-print-front` : front Nuxt.

L'API et le worker doivent partager le dossier des données (`DATA_DIR`, volume `app_data`) : les documents y attendent d'être imprimés.

## Configuration

### API

| Variable | Rôle | Défaut |
|---|---|---|
| `DATABASE_URL` | Connexion PostgreSQL | — |
| `APP_SECRET` | Secret Symfony | — |
| `JWT_PASSPHRASE` | Passphrase des clés JWT (`config/jwt/`, à monter en volume) | — |
| `MESSENGER_TRANSPORT_DSN` | File des travaux d'impression | `doctrine://default` |
| `DATA_DIR` | Données de l'application : documents en attente (`print-jobs/`), imprimantes « dossier » (`print-folders/`) | `var/data` |
| `PRINT_MAX_FILE_SIZE` | Taille maximale d'un document, en octets. Au-delà de 16 Mo, augmentez aussi `upload_max_filesize` et `post_max_size` dans `docker/php.ini`. | `52428800` (50 Mo) |
| `PRINT_RETENTION_DAYS` | Jours de conservation des documents après l'impression | `7` |
| `PRINT_FOLDER_ROOT` | Dossier racine des imprimantes « dossier » | `DATA_DIR/print-folders` |
| `SMBCLIENT_BINARY` | Chemin de `smbclient` | `smbclient` |
| `SECRETS_ENCRYPTION_KEY` | Clé de chiffrement des secrets en base (mots de passe des imprimantes, de l'annuaire, secrets SSO). Vide : dérivée de `APP_SECRET`. La changer oblige à ressaisir les mots de passe. | — |
| `CORS_ALLOW_ORIGIN` | Origines autorisées à appeler l'API depuis un navigateur (regex) | localhost |
| `SETUP_TOKEN` | Jeton demandé par la page de configuration initiale | — |
| `UPDATE_REPOSITORY` | Dépôt GitHub dont les nouvelles versions sont signalées. Voir [Mises à jour](/administration/updates). | `fayouz/rocket-print` |
| `UPDATER_TOKEN` | Active la mise à jour en un clic, avec le service `updater` (profil `updater`) | — |
| `RUN_MIGRATIONS` | `1` pour appliquer les migrations au démarrage du conteneur | `0` |

Les variables LDAP sont décrites dans [Utilisateurs et LDAP](/administration/users-ldap).

### Autonome ou dans la suite Rocket

Par défaut, Rocket Print est **autonome** : il gère ses comptes (locaux, LDAP, fournisseurs OpenID Connect). Dans la **suite** Rocket, la connexion passe par Rocket Auth, qui gère aussi les utilisateurs, les groupes et l'annuaire :

| Variable | Rôle | Défaut |
|---|---|---|
| `ROCKET_AUTH_URL` | Adresse publique de Rocket Auth. Renseignée : mode suite. | — |
| `ROCKET_AUTH_INTERNAL_URL` | Adresse de Rocket Auth vue par l'API (ex. `http://auth-api` dans Docker) | l'adresse publique |
| `ROCKET_AUTH_CLIENT_ID`, `ROCKET_AUTH_CLIENT_SECRET` | Client OpenID Connect de Rocket Print, déclaré dans Rocket Auth | `rocket-print` |
| `ROCKET_AUTH_ADMIN_GROUP` | Groupe de Rocket Auth dont les membres administrent Rocket Print | `rocket-admins` |
| `ROCKET_LOCAL_LOGIN` | `1` : accès de secours par mot de passe local | `0` |
| `ROCKET_INTERNAL_URL` | Adresse de Rocket Print vue par le serveur de Rocket Auth (ex. `http://print-api` dans Docker) : Rocket Auth y envoie les déconnexions (back-channel logout) | `ROCKET_PUBLIC_URL`, sinon `FRONTEND_URL` |

En mode suite, se déconnecter de Rocket Auth, ou y être désactivé ou supprimé, ferme les sessions de l'utilisateur dans Rocket Print : Rocket Print déclare à Rocket Auth son adresse de déconnexion (`<ROCKET_INTERNAL_URL>/api/auth/oidc/backchannel-logout`) à la première connexion et avec `php bin/console rocket:suite:sync`.

Voir le [README de rocket-core](https://github.com/fayouz/rocket-core#modes-autonome-et-suite).

### Tâches planifiées

Le worker (`messenger:consume async scheduler_default`) lance lui-même :

- toutes les 5 minutes, la vérification des imprimantes actives, de l'annuaire et des fournisseurs SSO ;
- toutes les heures, la suppression des documents au-delà de `PRINT_RETENTION_DAYS`, et le passage en échec des travaux interrompus en cours d'impression (redémarrage du worker).

Avec LDAP, planifiez aussi la synchronisation de l'annuaire :

```bash [crontab]
*/30 * * * *  docker compose exec -T api php bin/console app:ldap:sync
```

### Front

| Variable | Rôle |
|---|---|
| `NUXT_PUBLIC_API_BASE` | URL de l'API vue par le navigateur. **Vide** : le front relaie `/api` vers l'API (une seule URL publique, pas de CORS). |
| `NUXT_API_INTERNAL_BASE` | URL de l'API vue par le serveur du front, ex. `http://api:80` |

::warning
En production, changez `APP_SECRET` et `JWT_PASSPHRASE`, montez les clés JWT dans un volume persistant et servez le front et l'API en **HTTPS**.
::
